¿Por qué GPU? Arquitectura comparada

Una CPU está optimizada para latencia: pocas unidades de cómputo muy potentes que ejecutan tareas complejas secuenciales con cachés grandes. Una GPU está optimizada para throughput: miles de núcleos simples que ejecutan la misma operación sobre grandes conjuntos de datos en paralelo.

// modelo conceptual de hardware

4–32 núcleos
Caché L3 grande
Control complejo

⟷

~16–32 GB/s
bidireccional
⟷
GPU
1,000–10,000+ núcleos
VRAM HBM/GDDR

Alto throughput
Regla de oro: La GPU es eficiente cuando el mismo código (kernel) se aplica en paralelo a millones de datos. Si el problema tiene mucha lógica condicional o dependencias secuenciales, la CPU es más rápida.

Flujo de ejecución CPU ↔ GPU

En CUDA, la CPU (host) orquesta la ejecución y la GPU (device) realiza el trabajo pesado. El flujo siempre sigue estos pasos:

  1. Asignación de memoria en la GPU Reservar espacio en la VRAM del device con cudaMalloc(). La memoria del host y del device son espacios separados.
  2. Transferencia Host → Device (H2D) Copiar los datos de la RAM (host) a la VRAM (device) con cudaMemcpy(dst, src, size, cudaMemcpyHostToDevice).
  3. Lanzamiento del Kernel La CPU invoca la función paralela en la GPU con la sintaxis kernel<<<grid, block>>>(args). La CPU continúa sin esperar (llamada asíncrona).
  4. Sincronización (opcional pero frecuente) cudaDeviceSynchronize() hace que la CPU espere a que todos los hilos GPU terminen.
  5. Transferencia Device → Host (D2H) Copiar los resultados de vuelta a la RAM del host con cudaMemcpy(dst, src, size, cudaMemcpyDeviceToHost).
  6. Liberación de memoria cudaFree() libera la memoria del device. El host libera su memoria con free() como siempre. 
// Ejemplo completo: suma de vectores (flujo típico)
int N = 1024;
size_t bytes = N * sizeof(float);

// 1. Asignación en device
float *d_A, *d_B, *d_C;
cudaMalloc(&d_A, bytes);
cudaMalloc(&d_B, bytes);
cudaMalloc(&d_C, bytes);

// 2. H2D
cudaMemcpy(d_A, h_A, bytes, cudaMemcpyHostToDevice);
cudaMemcpy(d_B, h_B, bytes, cudaMemcpyHostToDevice);

// 3. Lanzar kernel
int blockSize = 256;
int gridSize  = (N + blockSize - 1) / blockSize;
addVectors<<<gridSize, blockSize>>>(d_A, d_B, d_C, N);

// 4. Sincronizar
cudaDeviceSynchronize();

// 5. D2H
cudaMemcpy(h_C, d_C, bytes, cudaMemcpyDeviceToHost);

// 6. Liberar
cudaFree(d_A); cudaFree(d_B); cudaFree(d_C);

El Kernel: función en el dispositivo

Un kernel es una función C/C++ marcada con el calificador __global__ que se ejecuta en la GPU. CUDA lanza automáticamente tantas instancias de esta función como hilos se configuren en el lanzamiento.

Clave conceptual: Cada hilo ejecuta el mismo código, pero actúa sobre un dato diferente según su identificador único. Esto se llama modelo SIMT (Single Instruction, Multiple Threads).

Calificadores de función

CalificadorSe ejecuta enSe llama desdeUso
__global__ GPU (device) CPU (host) o GPU Kernels principales — punto de entrada paralelo
__device__ GPU (device) Solo GPU Funciones auxiliares llamadas desde kernels
__host__ CPU (host) Solo CPU Funciones normales (implícito por defecto) 
// Kernel simple: suma de vectores
__global__ void addVectors(float* A, float* B, float* C, int N) {
    // Cada hilo calcula su índice global único
    int i = blockIdx.x * blockDim.x + threadIdx.x;

    // Guardia: evitar acceso fuera de rango
    if (i < N) {
        C[i] = A[i] + B[i];  // operación paralela
    }
}

// Función __device__: usable solo dentro de kernels
__device__ float activateReLU(float x) {
    return x > 0.0f ? x : 0.0f;
}

// Kernel que llama función __device__
__global__ void applyReLU(float* data, int N) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < N) data[i] = activateReLU(data[i]);
}

Jerarquía de hilos y dimensionalidad

CUDA organiza los hilos en una jerarquía de dos niveles: el Grid (cuadrícula) contiene bloques, y cada Bloque contiene hilos. Tanto bloques como hilos pueden organizarse en 1D, 2D o 3D.

// jerarquía de ejecución CUDA
🟣 Grid
Conjunto de todos los bloques. Se lanza por kernel.
gridDim.x / .y / .z
blockIdx.x / .y / .z
🔵 Block
Grupo de hilos que comparten memoria compartida y pueden sincronizarse.
blockDim.x / .y / .z
threadIdx.x / .y / .z
🟢 Thread
Unidad mínima de ejecución. Cada uno corre el mismo kernel con ID único.
Identificado por:
(blockIdx, threadIdx)

Configuración por dimensionalidad

La elección de dimensiones debe reflejar la estructura natural de los datos:

1D
Arrays, vectores, series temporales, audio.
dim3 block(256); dim3 grid(N/256); kernel<<<grid, block>>>()
2D
Matrices, imágenes, multiplicación matricial.
dim3 block(16, 16); dim3 grid(W/16, H/16); kernel<<<grid, block>>>()
3D
Volúmenes, voxels, tensores, simulaciones 3D.
dim3 block(8, 8, 8); dim3 grid(X/8,Y/8,Z/8); kernel<<<grid, block>>>()
Límites de hardware: El número máximo de hilos por bloque es 1024 (en GPUs modernas). Para bloques 2D: 16×16=256 o 32×32=1024. Para bloques 3D: 8×8×8=512 o 8×8×16=1024. 
// Ejemplo: kernel 2D para procesamiento de imagen
__global__ void grayscale(uchar3* input, unsigned char* output, int width, int height) {
    int col = blockIdx.x * blockDim.x + threadIdx.x;  // coordenada x (columna)
    int row = blockIdx.y * blockDim.y + threadIdx.y;  // coordenada y (fila)

    if (col < width && row < height) {
        int idx = row * width + col;  // índice lineal en memoria
        uchar3 pixel = input[idx];
        output[idx] = 0.299f * pixel.x + 0.587f * pixel.y + 0.114f * pixel.z;
    }
}

// Lanzamiento
dim3 blockDim(16, 16);
dim3 gridDim( (width + 15) / 16, (height + 15) / 16 );
grayscale<<<gridDim, blockDim>>>(d_input, d_output, width, height);

Cálculo de índices globales

El cálculo del índice global es el núcleo de la programación CUDA: permite que cada hilo sepa qué elemento debe procesar.

1D — Caso base

i = blockIdx.x × blockDim.x + threadIdx.x

2D — Para matrices e imágenes

col = blockIdx.x × blockDim.x + threadIdx.x
row = blockIdx.y × blockDim.y + threadIdx.y
idx = row × width + col

3D — Para volúmenes/tensores

x = blockIdx.x × blockDim.x + threadIdx.x
y = blockIdx.y × blockDim.y + threadIdx.y
z = blockIdx.z × blockDim.z + threadIdx.z
idx = z × (dimX × dimY) + y × dimX + x
Guardia de rango: Siempre verificar if (i < N) antes de acceder a memoria. Si N no es múltiplo del tamaño de bloque, los hilos excedentes existirán pero no deben leer/escribir memoria válida.

Modelo de memoria CUDA

CUDA tiene una jerarquía de tipos de memoria con diferentes velocidades, ámbitos y capacidades. Entender esta jerarquía es crítico para el rendimiento.

Tipo Ubicación Velocidad Ámbito Declaración
Registros Chip (SM) Muy rápido Por hilo Variables locales automáticas
Memoria compartida Chip (SM) Muy rápido Por bloque __shared__
Memoria global VRAM (off-chip) ~400–800 ciclos Todo el kernel cudaMalloc()
Memoria constante VRAM + caché L1 Rápido si hit Solo lectura __constant__
Memoria de textura VRAM + caché 2D Rápido + filtrado Solo lectura Objeto de textura
Memoria local VRAM (spill) Lento Por hilo Automático (desborde de registros)

Memoria compartida: el truco de rendimiento

La memoria compartida (__shared__) es ~100× más rápida que la global. El patrón clásico es cargar datos en shared memory, sincronizar hilos con __syncthreads(), y operar sobre ella.

__global__ void matMulShared(float* A, float* B, float* C, int N) {
    __shared__ float tileA[16][16];  // tile en memoria compartida
    __shared__ float tileB[16][16];

    int tx = threadIdx.x, ty = threadIdx.y;
    int row = blockIdx.y * 16 + ty;
    int col = blockIdx.x * 16 + tx;
    float sum = 0.0f;

    for (int t = 0; t < N / 16; t++) {
        tileA[ty][tx] = A[row * N + (t * 16 + tx)];  // carga cooperativa
        tileB[ty][tx] = B[(t * 16 + ty) * N + col];
        __syncthreads();                                // barrera de bloque

        for (int k = 0; k < 16; k++) sum += tileA[ty][k] * tileB[k][tx];
        __syncthreads();
    }
    C[row * N + col] = sum;
}

Mapeo de funciones CPU → GPU

Toda operación que en CPU se hace con un bucle for sobre datos, puede mapearse a un kernel donde cada iteración es un hilo.

// equivalencia CPU ↔ GPU

🖥️ CPU (Secuencial)

for i in range(N)
for (i=0; i<N; i++)
for (row=0; ...)
for (col=0; ...)
Array local
Función normal
malloc / free
→ → → → → → →

⚡ GPU (Paralelo)

1D kernel: threadIdx.x
1D kernel con guardia
2D kernel: blockIdx.y
2D kernel: blockIdx.x
__shared__ / global mem
__global__ / __device__
cudaMalloc / cudaFree

Ejemplo de transformación

// ── CPU: función map sobre array ──────────────────────
void squareCPU(float* data, int N) {
    for (int i = 0; i < N; i++) {
        data[i] = data[i] * data[i];  // iteración secuencial
    }
}

// ── GPU: mismo trabajo, todos los hilos en paralelo ───
__global__ void squareGPU(float* data, int N) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;  // reemplaza el loop
    if (i < N) data[i] = data[i] * data[i];
}

// ── CPU: reducción (suma) ─────────────────────────────
float sumCPU(float* data, int N) {
    float total = 0;
    for (int i = 0; i < N; i++) total += data[i];
    return total;
}

// ── GPU: reducción paralela con memoria compartida ────
__global__ void sumGPU(float* data, float* result, int N) {
    __shared__ float partial[256];
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    partial[threadIdx.x] = (i < N) ? data[i] : 0.0f;
    __syncthreads();

    for (int stride = blockDim.x / 2; stride > 0; stride /= 2) {
        if (threadIdx.x < stride) partial[threadIdx.x] += partial[threadIdx.x + stride];
        __syncthreads();
    }
    if (threadIdx.x == 0) atomicAdd(result, partial[0]);
}

Patrón completo: de idea a kernel

Para diseñar cualquier kernel, seguir este proceso mental:

  1. Identificar el paralelismo ¿Qué operación se repite independientemente? Un bucle for cuyos iteraciones no dependen entre sí es candidato ideal.
  2. Elegir la dimensionalidad ¿Los datos son 1D (vector), 2D (imagen/matriz) o 3D (volumen)? La dimensionalidad del kernel debe reflejar la del problema.
  3. Definir el trabajo por hilo Cada hilo procesa exactamente un elemento (o un tile con memoria compartida). Calcular el índice global a partir de blockIdx y threadIdx.
  4. Dimensionar el lanzamiento Elegir blockDim (típicamente 128, 256 o 512 hilos) y calcular gridDim = (N + blockDim - 1) / blockDim para cubrir todos los datos.
  5. Gestionar la memoria Usar __shared__ para datos accedidos múltiples veces por el mismo bloque. Asegurar accesos coalescentes a memoria global para máximo ancho de banda.
Regla de aceleradores: Una GPU solo vale la pena si el trabajo paralelo supera con creces la latencia de transferencia PCIe (H2D + D2H). Para datos pequeños (< ~100 KB) y operaciones simples, la CPU suele ser más rápida.
